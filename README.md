### 🎯 Задача
**Multi-label classification** - для каждого клиента предсказать набор из 24 банковских продуктов, 
которые он приобретёт в следующем месяце.

## 📊 Анализ данных (EDA выводы)

### Основные характеристики данных:
- **13.6 млн записей** за 17 месяцев (январь 2015 - май 2016)
- **956,645 уникальных клиентов** (в среднем 14.27 записей на клиента)
- **48 признаков**, включая 24 целевых переменных (банковских продукта)
- **Временной ряд**: ежемесячные снимки состояния клиентов

### Ключевые проблемы данных:
1. **Пропуски в данных**:
   - `renta` (доход): 20.5% пропусков (2.8 млн записей)
   - `conyuemp`, `ult_fec_cli_1t`: >99% пропусков
   - Остальные признаки: 0.2-1.4% пропусков

2. **Выбросы**:
   - Возраст: максимальное значение 164 года (аномалия)
   - Доход: максимальное значение 28.9 млн (экстремальный выброс)
   - Стаж: отрицательные значения (-999999)

3. **Дисбаланс целевых переменных**:
   - Самый популярный продукт (`cco` - текущий счёт): 65.5% клиентов
   - Самый редкий продукт (`aval` - банковская гарантия): 0.0023% клиентов
   - 7 продуктов имеют менее 1% распространения

## Подход к решению

### 1. Предобработка данных
#### Обработка пропусков:
- **Удаление**: `conyuemp`, `ult_fec_cli_1t` (>99% пропусков)
- **Доход**: заполнение медианой по сегменту, полу и возрастной группе
- **Категориальные переменные**: заполнение модой или создание категории "UNKNOWN"
- **Числовые переменные**: заполнение медианой

#### Обработка выбросов:
- **Возраст**: ограничение диапазоном 18-100 лет
- **Стаж**: отрицательные значения → 0, ограничение 600 месяцев
- **Доход**: логарифмирование для уменьшения влияния выбросов

#### Feature Engineering:
- **Демографические группы**: возрастные группы, квартили дохода, группы стажа
- **Временные признаки**: месяц, квартал, время с регистрации
- **Статистики клиента**: количество продуктов, индикатор нового клиента
- **Кодирование категорий**: 
  - One-Hot Encoding для переменных с малым количеством категорий
  - Frequency Encoding для переменных со многими категориями

### 2. Выбор моделей
**Основные кандидаты**:
1. **LightGBM** - градиентный бустинг, эффективен с категориальными признаками
2. **Random Forest** - простой и надежный подход к решению

**Стратегия обучения**:
- Использование временного сплита (train: первые 16 месяцев, test: последний месяц)
- Стратифицированное разбиение для учёта дисбаланса
- Кросс-валидация с временными блоками (TimeSeriesSplit)

## 📈 Метрики оценки

### Основные метрики:
1. **Precision@K** - точность среди K рекомендованных продуктов
   - K=5: учитываем топ-5 рекомендаций
   - Цель: >0.15 для топ-5

2. **Recall@K** - полнота среди K рекомендованных продуктов
   - K=5: как много из реально купленных продуктов попали в рекомендации
   - Цель: >0.10 для топ-5

3. **MAP@K** (Mean Average Precision) - средняя точность по K
   - K=5: основная метрика для ранжирования
   - Цель: >0.08 для топ-5
